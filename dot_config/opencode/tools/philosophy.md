## Code philosophy

Use philosophy skills as a review lens only when they are relevant to the requested change.

- Load `code-philosophy` for substantial new business logic, architecture, or error-handling work.
- Load `frontend-philosophy` only for web frontend work. Do not apply it to Android Compose or other native UI.
- Do not load either skill for trivial edits, configuration-only changes, or documentation-only work unless it adds clear value.
- Verify changed code against the selected checklist before completing.
- Never refactor unrelated code merely to satisfy a philosophy checklist.
- Preserve the project's existing architecture and style unless the task explicitly asks for broader changes.
